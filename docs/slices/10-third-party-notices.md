# Slice 10 – Third-party license notices

**Status:** 🚧 in progress

## Context

The installer contains compiled copies of many Rust crates and npm packages whose licenses (MIT, Apache-2.0, BSD, ISC, zlib, …) require their copyright and license notice to ship with every copy. Today nothing ships. This slice generates the notices, shows them in the app under „Licencje”, and makes CI fail when a dependency brings a license nobody reviewed.

User decisions (2026-10-28):
- **Display:** a dialog in the main window, opened only from a native menu item „Pomoc → Licencje…” (no button in the window). Plain text: Sito's own license, then Rust crates, then npm packages. No new window, no new Tauri permission, CSP unchanged.
- **Rust notices:** generated by `cargo-about`, **committed**, and CI regenerates them and fails on a diff or an unaccepted license. After a Rust dependency change, run one command to regenerate.

Answers to the slice's open questions: plain text (no HTML to sanitize); `cargo-about` only (it already fails on unaccepted licenses, so `cargo-deny` adds nothing yet); CI installs a prebuilt `cargo-about` with `taiki-e/install-action` (seconds, no compile).

## Implementation

### 0. Docs
- Save this plan into `docs/slices/10-third-party-notices.md`, status 🚧 there and in `docs/ROADMAP.md`. Commit `docs: add slice 10 plan`.

### 1. Rust notices (`cargo-about`)
- Root `about.toml`: `accepted = [...]` (the licenses actually found, reviewed: MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-2/3-Clause, ISC, Zlib, Unicode-3.0, MPL-2.0 if present, …), `targets = [x86_64-pc-windows-msvc, aarch64-apple-darwin, x86_64-apple-darwin]` so the output is the same on every machine, `ignore-dev-dependencies = true`, `ignore-build-dependencies = true`, `private = { ignore = true }` (our own crates; set `publish = false` on `sito` and `sito-core` if not already). Add clarifications only for crates whose license files cargo-about cannot find (e.g. `ring` if present).
- Root `about.hbs`: plain-text template, one section per distinct license text, listing the crates (name + version) that use it, then the full text.
- Output: `ui/notices/rust-crates.txt` (committed). Script `npm run notices:rust` = `cargo about generate --locked --fail about.hbs -o ui/notices/rust-crates.txt`.
- Commit `chore: generate Rust third-party notices with cargo-about`.

### 2. npm notices (own Vite plugin, no new dependency)
`rollup-plugin-license` targets Rollup (Vite 8 uses Rolldown) and pulls in lodash + moment, so a small plugin instead, in `ui/build/` (included in `tsconfig.node.json`):
- `ui/build/thirdPartyNotices.ts` – pure domain functions, unit-tested with Vitest:
  - `packageOf(moduleId)` → package name/root from a `node_modules/...` path (scoped packages, nested `node_modules`), `null` for our own sources.
  - `checkLicenses(packages, allowed)` → list of packages whose SPDX `license` is missing or not on the allow-list.
  - `formatNotices({ sito, rust, npm })` → the one combined text: header, Sito's license (MIT OR Apache-2.0 with both texts from `LICENSE-MIT`/`LICENSE-APACHE`), the Rust file, then npm packages sorted by name with version, license and full license file text.
- `ui/build/thirdPartyNoticesPlugin.ts` – the I/O: in `generateBundle`, collect the module ids of all chunks, read each package's `package.json` and `LICENSE*`/`LICENCE*`/`COPYING*` file, fail the build (`this.error`) on a disallowed or missing license or missing license text, and `emitFile` `THIRD-PARTY-NOTICES.txt` into `dist`.
- `vite.config.ts`: add the plugin (build only, `apply: 'build'`).
- Since `ui/dist` is embedded into the app binary, the notices ship with every copy on Windows and macOS without Tauri resources.
- Commit `feat: bundle third-party notices into the frontend build`.

### 3. „Licencje” dialog (UI, feature `about`)
- `ui/src/features/about/api.ts` – `loadNotices()`: `fetch('/THIRD-PARTY-NOTICES.txt')`, validates it is text (not the dev server's HTML fallback), returns a discriminated result.
- `ui/src/features/about/LicensesDialog.tsx` (+ `.css`): native `<dialog>` opened with `showModal()` (Esc and focus trapping built in, no own `keydown`), heading „Licencje”, the version (`getVersion()` from `@tauri-apps/api/app` via `api.ts`, already allowed by `core:default`), states `loading | error | ready` as a union, text in a scrollable `<pre>` (a few hundred KB; one text node, no virtualization needed), „Zamknij” button.
- **Opened only from a native menu item, no button in the window:** `src-tauri/src/about.rs` builds the main window's menu „Pomoc” → „Licencje…” (Windows: just that submenu; macOS: Tauri's default menu with the item added to its Help submenu, so Copy/Paste/Quit stay). A click emits `about-show-licenses` to the main window. The menu labels are Polish strings in Rust (native menus can't use `pl.json`); they stay in one place in `about.rs` until slice 22 adds languages.
- `api.ts` wraps `listen('about-show-licenses')`; a hook `useLicensesDialog` in `App.tsx` opens the dialog, so it works on the start screen and over the timeline.
- Strings in `pl.json` (`about.licenses`, `about.close`, `about.loading`, `about.loadError`, `about.version`).
- Tests: Vitest (dialog opens on the event, shows text, error state, closes) with `api.ts` mocked; Rust unit test for the menu-id → action mapping; Playwright `ui/e2e/licenses.spec.ts` emits the mocked event and routes `/THIRD-PARTY-NOTICES.txt` to a fixture text.
- Commit `feat: show third-party licenses in the app`.

### 4. CI
- `ci.yml`, new job `licenses` (ubuntu-latest): checkout, `taiki-e/install-action` with `cargo-about`, `npm run notices:rust`, `git diff --exit-code ui/notices/` (stale or unaccepted license → red). The npm check runs in the existing `npm run build` steps (plugin fails on a disallowed license).
- Commit `ci: check third-party licenses`.
